## 1. 没必要100%还原现实世界

每个东西都要设计可交互类型 可是直接枚举可交互类型又不现实 那就设置软度 硬度 以及力量 重量等

游戏世界本就是虚拟, 不能把所有的物理现象实现的很细节, 因为太难了, 应该适当简化, 符合直觉就行(比如抽象物质的组成事, 现实世界的物质, 金属就有几十种, 还有各种石头, 硬度都不同, 全部罗列出来太复杂, 这时候就要适当简化, 把一些没必要的东西删掉, 比如剑就是金属制成的, 金属可以导电, 金属硬度较高, 这样就行了, 如果不够, 就加个软金属, 液体金属等)

比如: 玩家不需要知道铁、铜、铝的电导率差异，他们只需要知道“金属”这个概念会引来雷电, 玩家可以利用现实世界的直觉快速上手

近距离武器用来击打 (不可以有过多操作 游戏手柄按键有限) 弓箭只能用来射箭(不可以用来击打, 这就是需要简化, 不能说弓箭还可以进行击打还可以射箭, 这样的逻辑太复杂了, 这是著名的**“真实性陷阱 (The Realism Trap)”**, 游戏的核心是**体验 (Experience)**，而非**模拟 (Simulation)**

追求“完全真实”，结果导致玩法笨重或重复, 过于真实的系统往往意味着大量的维护性工作，比如过于频繁的武器保养、进食、清洁等，这些很快会变成无趣的重复劳动, 想象一下，如果游戏里需要考虑金属热胀冷缩导致武器卡壳，或者需要区分十几种螺丝来修理载具，这会把玩家的精力从核心冒险和战斗中抽离，变成繁琐的“模拟人生”

材质系统过于复杂，玩家和自己都维护不动

游戏物质系统本质上是一种“交互语言 (Language of Interaction)” 它的目的不是复刻现实世界，而是为玩家提供一套清晰、可预测且富有创造空间的规则，让他们能够理解世界并与之互动

## 2. 如何取舍

### 2.1. 取舍的核心原则：为核心玩法服务 (Serve the Core Gameplay)

在设计任何材质属性之前，先问自己一个问题：“这个设计能为我的核心玩法带来什么？

**如果游戏核心是战斗**: 材质系统应该服务于战斗策略。例如，木制盾牌防火性差但能浮空，金属盾牌防火但导电。《塞尔达传说：旷野之息》就是典范

**如果游戏核心是建造与生存**: 材质系统应该服务于资源管理和创造。例如，木头易获取但脆弱，石头坚固但沉重，黑曜石坚硬但需要特殊工具开采。《Minecraft》的系统简单却深刻

**如果游戏核心是解谜**: 材质系统应该服务于谜题的逻辑链。例如，某种液体可以导电，某种凝胶可以反弹光线。《Portal 2》中的凝胶就是典型的为解谜服务的“物质”

**取舍实践**: 砍掉所有不能直接或间接增强核心玩法的材质属性。一把剑的“熔点”属性，在大多数游戏里都是无用信息，除非你的游戏里有龙息或熔岩锻造的核心玩法

### 2.2. 取舍的平衡点：深度 vs. 复杂度

- **复杂度 (Complexity)**: 指的是系统规则的数量和记忆负担。比如有100种不同的矿石
- **深度 (Depth)**: 指的是利用有限的规则能产生多少有意义的、丰富的**玩法组合** 比如只有“火、水、电、冰”四种元素和“木、石、金、布”四种材质

**目标永远是追求“高深度、低复杂度”**

**取舍实践**: 与其设计20种效果单一的金属，不如设计3种基础金属（如：轻金属、重金属、魔法金属），但让它们与游戏中的元素系统（火、冰、电）、物理系统（重量、浮力）、状态系统（潮湿、燃烧、冰冻）产生丰富的**“化学反应 (Systemic Interaction)”**

例如，一个简单的交互矩阵：

| 火焰 (Fire) | 闪电 (Lightning) | 水 (Water) |            |
| ----------- | ---------------- | ---------- | ---------- |
| **木材**    | 燃烧             | 无影响     | 潮湿、可浮 |
| **金属**    | 导热             | 传导、引雷 | 下沉、生锈 |

仅仅2个材质和3个元素，就创造出了多种策略选择和环境故事。这就是用简单的规则创造深度

### 2.3. 取舍的方法论：从“概念标签”出发 (Start with "Gameplay Tags")

不要从模拟物理属性开始，要从定义“玩法标签”开始

- 传统思路 (易入陷阱): 铁 -> 密度7.8g/cm³, 熔点1538°C, 电阻率9.71×10⁻⁸ Ω·m... (复杂且无用)
- 游戏设计思路 (高效实用):
  1. 定义基础材质: 木头 (Wood), 石头 (Stone), 金属 (Metal), 布料 (Cloth), 液体 (Liquid), 植物 (Plant)...
  2. 为材质打上“玩法标签”:
     - 木头: `Flammable` (可燃), `Buoyant` (可浮), `Low_Durability` (低耐久)
     - 金属: `Conductive` (导电), `High_Durability` (高耐久), `Heavy` (重), `Heat_Conductive` (导热)
     - 布料: `Flammable`, `Lightweight` (轻), `Absorbent` (可浸湿)
  3. 定义“行为”与“标签”的交互规则:
     - 行为 `Fire_Attack` 作用于带 `Flammable` 标签的物体 -> 施加 `Burning` 状态
     - 行为 `Electric_Attack` 作用于带 `Conductive` 标签的物体 -> 产生范围伤害
     - 天气 `Rain` 作用于带 `Absorbent` 标签的物体 -> 施加 `Wet` 状态
     - 状态 `Wet` + `Flammable` -> 暂时移除 `Flammable` 标签

这种基于标签的系统清晰、易于管理和扩展。当你想创造一个新物质，比如“浸油的布”，你只需要给它加上 `Flammable` 和 `Absorbent` 标签，它就能自动继承所有相关的交互逻辑

## 3. 举例

设计方案: 通过抽象出五大基础属性来构建物质, 然后**通过标签为物质加上特性**

物体只描述“静态属性”

- 如 `density`、`hardness`、`toughness`、`flammability_threshold`、`conductivity`…属性是有限的、通用的

所有**行为逻辑都写在规则模块**里

- 火、水、电、压力、酸液……每种交互在规则中描述“在什么条件下会产生什么结果”，而不是贴在物体上

| 旧做法：行为枚举               | 新做法：属性 + 规则                                |
| ------------------------------ | -------------------------------------------------- |
| `Tree.is_flammable = true`     | `Tree.flashpoint = 300 Tree.heat_capacity = 2.0`   |
| `Tree.can_be_corroded = false` | `Tree.toughness = 10`                              |
| `Rock.can_be_chopped = false`  | `Rock.hardness = 6 Rock.toughness = 20`            |
| ……一旦新交互，数十个类要改！   | 只需在规则中新增“酸液”“腐蚀”逻辑，所有物体自动兼容 |

避免标签爆炸：你不必为每个物体维护成百上千个 `can_xxx`

可维护性强：属性和规则分离，彼此解耦

> 也就是说 我们只给物体定义静态属性 至于交互反映 我们写道函数里 根据动态的参数 进行调整物体(生物) 的静态属性 进而影响生物的状态
>
> ```js
> // 例如：野狼
> {
>    "mass": 30,
>    "toughness": 50,
>    "hardness": 3,
>    "friction": 0.8,
>    "conductivity": 0.1,
>    "flashpoint": 200,
>    ...
> }
> ```
>
> 它不“知道”自己怕火、电、水、石头，它只是一个数据结构

**交互逻辑都写在统一的规则函数中**（Rules）

这些规则函数像“自然法则”，例如：

```js
func apply_heat(target, temperature):
    if temperature > target.flashpoint:
        target.status = "burning"

func apply_impact(target, kinetic_energy, attacker_hardness):
    if attacker_hardness > target.hardness:
        var damage = kinetic_energy / DAMAGE_COEFF
        target.toughness -= damage
        if target.toughness <= 0:
            target.die()
```

每种交互（热、冲击、电、腐蚀）都有一组对应的规则，**只关心物体的属性和当前环境/攻击的动态输入参数**

不是“木头知道自己会浮起来”，而是：
 “有一条规则：`if density < water_density → apply upward force`”

不是“野狼知道会怕滚石”，而是：
 “有一条规则：`if impact force > toughness → 减少 HP，可能死亡`”

如果你用 Godot 实现：

- 属性定义 → 放在每个对象的 `export var` 或脚本里的字典中
- 规则函数 → 写成 `GlobalRules.gd`，其他脚本调用统一接口即可
- 状态更新 → 物体自己监听属性变化，改变自身行为（如 burning → 扣血）
