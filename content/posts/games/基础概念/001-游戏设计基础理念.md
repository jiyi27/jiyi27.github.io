## 1. Perception is reality

> 不要去模拟“真实世界”（那个太复杂了）要去模拟“玩家觉得合理的世界”, 只要玩家觉得“这玩意儿看起来像铁，所以它导电”, 设计就成功了 (游戏规则不必真实, 但必须“自洽”)

游戏是“压缩后的世界”, 游戏规则应该像

- 把复杂系统压缩成直觉
- 把物理学变成几条可理解的规律
- 把世界变成玩家能掌控的系统

你不是在造世界, 你是在造“让玩家能理解的世界模型”, 游戏设计永远是: 忠于玩家的直觉, 而不是忠于现实

玩家不是科学家, 不会检验你是否真实, 但玩家极敏感于规则是否一致, 反馈是否合理

因此:

- 一致性 > 真实性
- 可理解性 > 复杂性
- 直觉 → 认知模型 → 玩法深度

这是真正优秀的游戏设计底层逻辑

> 《塞尔达》：金属武器真的会引雷, 但木头武器完全不导电——现实里木头湿了也会导, 但没人抱怨, 因为“玩家常识” 里木头=绝缘
>
> 几乎所有游戏里的枪：后坐力永远比现实小10倍，子弹永远直线飞，换弹夹时弹匣里的子弹自动消失……但玩家觉得“对，这就是枪”

## 2. Gameplay Tags

不要从模拟物理属性开始, 要从定义“玩法标签”开始

- 传统思路 (易入陷阱): 铁 -> 密度7.8g/cm³, 熔点1538°C, 电阻率9.71×10⁻⁸ Ω·m... (复杂且无用)
- 游戏设计思路 (高效实用):
  1. 定义基础材质: 木头 (Wood), 石头 (Stone), 金属 (Metal), 布料 (Cloth), 液体 (Liquid), 植物 (Plant)...
  2. 为材质打上“玩法标签”:
     - 木头: `Flammable` (可燃), `Buoyant` (可浮), `Low_Durability` (低耐久)
     - 金属: `Conductive` (导电), `High_Durability` (高耐久), `Heavy` (重), `Heat_Conductive` (导热)
     - 布料: `Flammable`, `Lightweight` (轻), `Absorbent` (可浸湿)
  3. 定义“行为”与“标签”的交互规则:
     - 行为 `Fire_Attack` 作用于带 `Flammable` 标签的物体 -> 施加 `Burning` 状态
     - 行为 `Electric_Attack` 作用于带 `Conductive` 标签的物体 -> 产生范围伤害
     - 天气 `Rain` 作用于带 `Absorbent` 标签的物体 -> 施加 `Wet` 状态
     - 状态 `Wet` + `Flammable` -> 暂时移除 `Flammable` 标签

这种基于标签的系统清晰, 易于管理和扩展, 当你想创造一个新物质, 比如“浸油的布”, 你只需要给它加上 `Flammable` 和 `Absorbent` 标签, 它就能自动继承所有相关的交互逻辑

> 为了不复杂的实现, 一个东西只有一个主材料, 主材料主岛其性质

## 3. 举例 - 设计哲学

1. 不是模拟真实世界，而是模拟玩家觉得合理的世界
2. 世界只存两样东西：静态属性（它是什么材料） + 动态标签+时间戳（它现在什么状态）
3. 全世界只有一张“自然法则表”（`GlobalRules.gd`），所有交互都在这里定义
4. 所有信息传递只靠全局事件总线（`signal`），完全解耦
5. 只有被观察（玩家/AI 靠近）时才计算现在应该是什么样子 → 量子观察者模式，CPU 几乎 0 负担
6. 玩家觉得“像真的”就真的，不模拟真实物理，只模拟玩家的童年常识

> 避免 `GlobalRules` 变成“上帝对象”, 如果所有东西的逻辑都往 GlobalRules 里堆, 那 GlobalRules 可能会变得过于巨大, 维护困难, 我们可以拆成多个模块:
>
> - `DecayRules.gd`
> - `FireRules.gd`
> - `ScentRules.gd`
> - `StatusRules.gd`
>
> 最外面 `GlobalRules.gd` 只是一个“统一入口”, 内部再去调这些模块

`static_props` 和 `dynamic_tags` 到底该怎么分工？会不会重复？

| 名字         | 回答的问题     | 能不能变？ | 举例                                  | 存档大小 |
| ------------ | -------------- | ---------- | ------------------------------------- | -------- |
| static_props | “是什么东西”   | 永不改变   | 我是“木头”做的 → 易燃、密度0.6、硬度2 | 超小     |
| dynamic_tags | “处于什么状态” | 随时在变   | 我现在“着火了”“湿了”“烂了”“被诅咒了”  | 小       |

首先 `static_props` 可以再抽像一层, 把世界简化成“只有 8 种基础材料”

```bash
# Autoload/MaterialDatabase.gd
extends Node

enum MaterialType {
    WOOD, STONE, METAL, FLESH, PLANT, CLOTH, BONE, GLASS, COPPER
}

const MATERIAL_DATA = {
    MaterialType.WOOD:    { density=0.6, hardness=2,  toughness=20,  flashpoint=300,  conductivity=0.01 },
    MaterialType.METAL:   { density=7.8, hardness=6,  toughness=80,  flashpoint=1500, conductivity=0.95 },
    # 其他省略……
}

static func get(material : MaterialType) -> Dictionary:
    return MATERIAL_DATA[material]
```

实体基类（所有东西都继承这一个, 注意 tag 很简单, 就是贴上一个动态标签 ）

```bash
# Entities/EntityBase.gd
extends Node2D
class_name EntityBase

# 把默认材质设为 WOOD, 没默认值会崩溃或隐藏 bug
@export var material : MaterialDatabase.MaterialType = MaterialDatabase.MaterialType.WOOD

# 允许个别装备覆盖属性（比如神器铁剑更硬）
@export var prop_overrides : Dictionary = {}

var tags : Dictionary = {}   # { "Burning": 1234567890, "Wet": null, ... }

func get_prop(key : String):
    if prop_overrides.has(key):
        return prop_overrides[key]
    return MaterialDatabase.get(material)[key]

func has_tag(tag : String) -> bool:
    return tags.has(tag)

func add_tag(tag : String, timestamp = null):
    if timestamp == null:
        timestamp = TimeManager.game_time
    tags[tag] = timestamp
    _on_tag_changed()

func remove_tag(tag : String):
    tags.erase(tag)
    _on_tag_changed()

# 当自己的tag变化时, 比如变为冰冻, 变为腐烂, 就会有对应的状态
func _on_tag_changed():
    # 这里刷新外观、粒子、音效
    get_node("Visualizer").update_from_tags(tags)
```

火的规则（全局只有这一段代码管所有燃烧, 简化了上面的每个规则组件）

```bash
# Autoload/GlobalRules.gd
static func try_apply_heat(entity : EntityBase, temperature : float):
    if entity.has_tag("Burning"): 
        return  # 已经在烧了
    
    var flashpoint = entity.get_prop("flashpoint")  # 自动读材料或override
    
    if temperature > flashpoint:
        entity.add_tag("Burning")
        print(entity.name + " 被点燃了！材料: " + str(entity.material))
```

一把剑的场景（只做一个 Sword.tscn）

```bash
# Entities/Sword.tscn
└── EntityBase (脚本上面那个)
    ├── Sprite2D          ← 初始贴图是铁剑外观
    ├── Visualizer.gd     ← 负责根据 material 和 tags 换贴图
    └── CollisionShape2D
```

```bash
# Visualizer.gd
@onready var sprite = $"../Sprite2D"
@onready var fire_particles = $"../FireParticles"

func update_from_tags(tags : Dictionary):
    var mat = get_parent().material
    
    # 根据材料换底
    match mat:
        MaterialDatabase.MaterialType.WOOD:  sprite.modulate = Color("d4a76a")
        MaterialDatabase.MaterialType.METAL: sprite.modulate = Color("cccccc")
        MaterialDatabase.MaterialType.COPPER:sprite.modulate = Color("b87333")
    
    # 根据标签显示燃烧
    fire_particles.emitting = tags.has("Burning")
    if tags.has("Burning"):
        sprite.modulate = Color("ff6600")  # 烧红了
```

> 其实这里没必要这么细节, 直接铁剑不会被烧就行了, 这里只是为了解释如何使用这个系统

放一个火堆（也继承 EntityBase，material=WOOD，add_tag("Burning")）, 然后把剑扔进火里：

```bash
# 火堆每秒执行一次
for entity in nearby_entities:
    GlobalRules.try_apply_heat(entity, 800)

# 木剑：flashpoint=300 → 800 > 300 → add_tag("Burning")
# 铁剑：flashpoint=1500 → 800 < 1500 → 什么都不发生
```

运行结果：

```
木剑 被点燃了！材料: 0        ← 300 < 800，烧！
```

> 标签系统的实现是整个系统有机的结合, 全局规则 appy 到某个物体, 若达成某个条件, 就会调用该物体的 `add_tag`, 这个时候 tag 添加的时间会被记录, 然后自动调用该物体自己的 `_on_tag_changed` 刷新外观
>
> 当然标签可以随时添加, 比如被攻击的时候的受伤状态, 冰冻了的冰冻状态, 可以由规则控制, 也可以由其他组件控制

Mini Rule Module

FireRules.gd —— 燃烧与火传播

```js
extends Node

func apply_material_rules(entity, now):
    var static = entity.get_node("StaticPropsComponent").props
    var tag = entity.get_node("TagComponent")

    var temp = entity.current_temperature
    var flash = static.flashpoint

    if temp > flash and not tag.has_tag("Burning"):
        tag.add_tag("Burning", now)

func apply_tag_rules(entity, now):
    var tag = entity.get_node("TagComponent")
    if tag.has_tag("Burning"):
        entity.toughness -= 1
        if entity.toughness <= 0:
            tag.add_tag("Charred", now)
            tag.remove_tag("Burning")
```

WetRules.gd —— 雨水、浸湿、灭火

```js
extends Node

func get_tag_rules():
    return {
        "Wet": {
            "blocks": ["Burning"],
            "lifetime": 1200,
            "on_expire": null
        }
    }

func apply_tag_rules(entity, now):
    var tag = entity.get_node("TagComponent")
    var rules = get_tag_rules()

    if tag.has_tag("Wet"):
        for blocked in rules["Wet"]["blocks"]:
            if tag.has_tag(blocked):
                tag.remove_tag(blocked)
```

ScentRules.gd —— 气味生成、衰减

```js
extends Node

func apply_tag_rules(entity, now):
    var tag = entity.get_node("TagComponent")
    var tags = tag.tags.keys()

    if "Rotten" in tags:
        ScentSystem.emit(entity.global_position, "stench", 80)

    if "Fresh" in tags:
        ScentSystem.emit(entity.global_position, "light_food", 20)
```

MaterialRules.gd —— 材质交互（导电、密度、浮沉）

```js
extends Node

func apply_material_rules(entity, now):
    var props = entity.get_node("StaticPropsComponent").props

    if props.density < 1.0 and entity.is_in_water:
        entity.apply_buoyancy()

    if props.conductivity > 0.5 and World.has_electric_field(entity.position):
        entity.apply_electric_damage()
```
