## 1. Area2D 和 CollisionShape2D 区别

角色吃金币的例子, 需要创建两个独立的“游戏对象”（即两个场景）：玩家 (Player) 和 金币 (Coin)

两个场景各自的节点树结构如下:

```js
▼ Player (CharacterBody2D)  <-- 根节点，决定了这是一个可移动、会碰撞的角色
  ▶ AnimatedSprite2D          <-- 子节点，决定了玩家长什么样
  ▶ CollisionShape2D          <-- 子节点，决定了玩家的物理形状
```

```
▼ Coin (Area2D)               <-- 根节点，决定了这是一个探测区域
  ▶ Sprite2D                  <-- 子节点，让它看起来像金币
  ▶ CollisionShape2D          <-- 子节点，定义了探测范围
```

关键脚本 `coin.gd`:

```js
extends Area2D

func _ready():
    # 监听 body_entered 信号, 由 Area2D 节点自身发出
    # 当有一个 PhysicsBody2D 进入这个 Area2D 的碰撞区时，Area2D 会发出 body_entered(body) 信号
    # body 参数是进入区域的那个物体（即 PhysicsBody2D 类型的节点）
    # 前提条件: 
	# 1. Area2D 本身必须有一个有效的 CollisionShape2D 或 CollisionPolygon2D 作为子节点
    # 2. 被触发的对象（比如玩家）必须是 PhysicsBody2D 的子类
    # 3. Area2D 必须启用 monitoring = true（默认是启用的）
    # 4. 被触发的 PhysicsBody2D 必须启用 collision_layer 和 collision_mask，并与 Area2D 的设置有交集
    connect("body_entered", self, "_on_body_entered")

func _on_body_entered(body):
    # 'body' 参数就是进入这个区域的那个节点, 也就是我们的玩家
    print("金币被吃掉了!")
```

整个流程串联起来就是：

1. 玩家移动：玩家的 `CharacterBody2D`（根节点）根据它的脚本移动, 带动着它的样子(`AnimatedSprite2D`)和形状(`CollisionShape2D`)一起动
2. 进入范围：当玩家的 `CollisionShape2D` 与金币的 `CollisionShape2D` 发生重叠...
3. 探测并发信号：金币的 `Area2D`（根节点）探测到了这个重叠，于是发出 `body_entered` 信号
4. 执行动作：金币脚本中连接到该信号的 `_on_body_entered` 函数被触发, 执行代码

> 是金币的 CollisionShape2D 检测 玩家的 CollisionShape2D 触发了 `_on_body_entered`, 还是 因为 玩家的根节点是一个 physic node, 才能被金币的 `_on_body_entered` 检测到?
>
> 简单回答：
>
> 谁负责探测？ `Area2D` (金币的根节点)
>
> 探测的对象是谁？ `CharacterBody2D` (玩家的根节点)
>
> 探测的依据是什么？ 两个节点各自的 `CollisionShape2D` 子节点所定义的区域发生了交集
>
> 详细回答:
>
> - `CollisionShape2D` 本身是一个数据容器, 它非常“笨”, 只负责一件事: **定义一个形状**（比如圆形、矩形、胶囊形）, 它自己没有探测或计算的能力
>
> - 真正执行探测工作的, 是它的父节点 `Area2D`: `Area2D` 从物理服务器获取信息, 不断地检查 “我（由我的 `CollisionShape2D` 子节点定义的范围）里面，有没有物理体进来了？
>
> 所以可以说 `CollisionShape2D` 提供了探测的“范围”, 但探测的“动作”是由 `Area2D` 完成的

> **注意**
>
> `Area2D` 的 `body_entered` 信号定义是“当一个 `PhysicsBody2D` 进入时发出”, 这里的 `PhysicsBody2D` 是一个基类, 包含: 
>
> - `CharacterBody2D`
> - `RigidBody2D`
> - `StaticBody2D`
> - `AnimatableBody2D` (较少用)
>
> 当金币的 `Area2D` 进行探测时，它只关心进入其范围的是不是以上这些“物理体”之一

## 2. `collision_layer` 和 `collision_mask` 的区别解释

### 2.1. 关键区别

- `collision_layer` (层): 我在哪？
  - 它声明了“我”属于哪个物理类别, 它像是在自己身上贴一个或多个标签，比如“我是玩家”、“我是敌人”、“我是子弹” (有咩有发现一些游戏敌人的子弹打不到敌人)
- `collision_mask` (掩码): 我关心谁？
  - 它定义了“我”想要与哪些类别的物体发生交互, 它像是一份清单, 上面写着：“我只关心‘墙壁’和‘机关’, 别的我都看不见”

也就是说只有当 A 的 `mask` (关心列表) 中包含了 B 的 `layer` (标签) 时, A 才能“看到”或“感知到” B

### 2.2. 与节点的关系

`collision_layer` 和 `collision_mask` 这两个属性存在于所有的**物理对象节点**上, 包括:

- `Area2D`
- `CharacterBody2D`
- `RigidBody2D`
- `StaticBody2D`

它们是这些物理节点的属性, 并不属于 `CollisionShape2D`, `CollisionShape2D` 只提供形状, 仅此而已

### 2.3. 举例解释

继续沿用“玩家吃金币”的例子, 并增加一个新元素：“墙壁”

1. 玩家 (Player)：
   - 应该被墙壁挡住（物理碰撞）
   - 应该能捡起金币（区域探测）
   - 不应该被其他玩家挡住（如果有多人游戏）
2. 金币 (Coin)：
   - 应该能被玩家捡起
   - 不应该关心墙壁, 它可以生成在墙里（或者我们不关心它和墙的交互）
   - 不应该关心其他金币
3. 墙壁 (Wall)：
   - 应该能挡住玩家
   - 不应该和金币或任何其他东西交互

为了实现这个，我们需要规划我们的“层”(Layers), Godot 提供了 32 个层, 我们可以给它们命名以方便记忆

步骤 1: 命名物理层

在 Godot 编辑器的 `项目 -> 项目设置 -> 2D 物理` 中，你可以为层命名：

- Layer 1: `player`
- Layer 2: `coin`
- Layer 3: `wall`
- ... (其他层)

步骤 2: 为每个节点设置层和掩码

现在，我们为每个场景的根节点（物理节点）设置它们的 `collision_layer` 和 `collision_mask`

玩家 (CharacterBody2D)

- `collision_layer`: 设置为 `player` (第 1 层)
  - 含义: 向世界宣告“我是玩家”
- `collision_mask`: 设置为 `wall` (第 3 层)
  - 含义: “我只关心‘墙壁’对我产生的物理阻挡”
  - 注意: 玩家不需要在物理掩码(`collision_mask`)中关心`coin`, 因为物理碰撞（被挡住）和区域探测（吃金币）是分开的, 玩家是否能吃金币，取决于金币的设置

金币 (Area2D)

- `collision_layer`: 设置为 `coin` (第 2 层)
  - 含义: 向世界宣告“我是金币”
- `collision_mask`: 设置为 `player` (第 1 层)
  - 含义: “我作为一个探测区域，只关心‘玩家’是否进入我”, 当一个 `layer` 为 `player` 的物体进入时，我就会发出 `body_entered` 信号

墙壁 (StaticBody2D)

- `collision_layer`: 设置为 `wall` (第 3 层)
  - 含义: 向世界宣告“我是墙壁”
- `collision_mask`: 可以不设置任何东西（保持为空）
  - 含义: “我是一个被动的物体, 我不需要主动关心任何东西, 我只是在这里, 谁想撞我谁来撞”

**交互流程分析**

现在，我们来看看交互是如何发生的

玩家 vs 墙壁 (物理碰撞)

- 玩家的 `layer` 是 `player`
- 墙壁的 `layer` 是 `wall`
- Godot 物理引擎检查：
  - 玩家的 `mask` 是否关心 `wall`？ 是
  - 墙壁的 `mask` 是否关心 `player`？ 否
- 结果：因为这是一个双向检查, 只要任意一方关心另一方, 物理碰撞就会发生, 所以玩家会被墙壁挡住, `CharacterBody2D` 的 `move_and_slide()` 会处理这个碰撞

玩家 vs 金币 (区域探测)

- 玩家的 `layer` 是 `player`
- 金币的 `layer` 是 `coin`
- 金币的 `Area2D` 检查：
  - “有一个物体进入了我的范围，它的 `layer` 是什么？” -> “是 `player`”
  - “我的 `mask` (关心列表) 里有 `player` 吗？” -> 有
- 结果：金币的 `Area2D` 确认了这是一个它关心的物体，于是发出 `body_entered` 信号

金币 vs 墙壁 (无交互)

- 金币的 `layer` 是 `coin`
- 墙壁的 `layer` 是 `wall`
- 金币的 `Area2D` 检查: “一个 `wall` 物体进入了我的范围, 我的 `mask` 关心 `wall` 吗？” -> 不关心
- 墙壁的 `StaticBody2D` 检查: “一个 `coin` 物体进入了我的范围, 我的 `mask` 关心 `coin` 吗？” -> 不关心
- 结果：什么都不会发生

## 3. Godot 常用 2D 节点速查表

| 节点 (Node)                     | 核心作用 (Core Function) | 主要使用场景 (Primary Use Cases)                             | 关键用法和细节 (Key Usage & Details)                         |
| ------------------------------- | ------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **Node2D**                      | “2D 世界的坐标点”        | 作为其他 2D 节点的容器或父节点，用于整体移动/旋转。需要一个有位置但无其他特性的空对象。 | 提供 `position`, `rotation`, `scale` 属性。所有 2D 视觉和物理节点都继承自它。 |
| **CharacterBody2D**             | “玩家和AI的骨架”         | 平台跳跃游戏的主角。俯视角游戏中由玩家或 AI 控制的角色。     | 物理体，但移动完全由代码控制。核心函数是 `move_and_slide()`，必须在 `_physics_process` 中使用。需要 `CollisionShape2D` 子节点。 |
| **RigidBody2D**                 | “物理世界的演员”         | 滚动的石头、被炸飞的箱子。遵循物理定律的任何可动物体。       | 完全由物理引擎驱动（重力、摩擦力、碰撞反弹）。不应直接修改其 `position`，而应通过 `apply_impulse()` 等函数施加力。需要 `CollisionShape2D` 子节点。 |
| **StaticBody2D**                | “世界的基石”             | 地面、墙壁、不可移动的平台。任何静态的物理障碍物。           | 静止的物理体，用于阻挡其他物体。计算开销小，非常高效。需要 `CollisionShape2D` 子节点。 |
| **Area2D**                      | “隐形的探测器”           | 收集品（金币、钥匙）。伤害/治疗区域（岩浆、圣光）。触发器（存档点、剧情对话）。 | 用于探测，不产生物理碰撞。核心是使用信号（Signals），尤其是 `body_entered` 和 `area_entered`。需要 `CollisionShape2D` 子节点来定义探测范围。 |
| **Sprite2D / AnimatedSprite2D** | “物体的样子”             | 角色的视觉表现、道具图标、背景元素。任何需要在屏幕上显示的图片或动画。 | `Sprite2D` 显示单张图片（`Texture` 属性）。`AnimatedSprite2D` 播放序列帧动画，需要创建 `SpriteFrames` 资源并在代码中用 `.play("动画名")` 来控制。 |
| **CollisionShape2D**            | “物理的形状”             | 所有物理体和区域节点的必备子节点。                           | **本身没有功能，必须作为物理体或 Area2D 的子节点。** 它为其父节点提供形状数据（矩形、圆形等）。一个父节点只能有一个 `CollisionShape2D`。 |
| **TileMap**                     | “关卡画笔”               | 平台游戏、RPG 或策略游戏的基于网格的关卡地图。               | 需要先创建 `TileSet` 资源，在其中为图块设置贴图、物理形状和导航。之后便可在编辑器中像画画一样构建关卡，非常高效。 |
| **Camera2D**                    | “玩家的眼睛”             | 跟随玩家移动。在关卡中平移、缩放、创造镜头效果。             | 决定游戏视口。通常作为玩家的子节点以实现自动跟随。可以启用 `Smoothing`（平滑）让镜头移动更自然。 |
| **AnimationPlayer**             | “万能动画师”             | UI 动效（淡入淡出）。让平台来回移动、门自动开关。制作复杂的过场动画。 | 极其强大，可为**任何节点**的**任何属性**（位置、颜色、脚本变量等）创建动画。比 `AnimatedSprite2D` 更灵活。 |
| **Timer**                       | “倒计时闹钟”             | 技能冷却、敌人生成计时。炸弹引信、限时任务。                 | 倒计时结束后发出 `timeout` 信号。在 Inspector 中设置 `Wait Time`（等待时间）和 `One Shot`（是否单次触发），在代码中用 `.start()` 启动。 |
